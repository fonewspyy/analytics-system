# ADR-0007: Backups live in a named Docker volume

* Status: accepted
* Date: 2026-10-21
* Requirements: R13 · Supersedes the backup location in ADR-0004

## Context

The brief (Day 3) asks for a `pg_dump` backup that is compressed and kept in a
designated volume (บีบอัดไฟล์เก็บไว้ใน Volume ที่กำหนด). ADR-0004 streamed the dump
out of the container into `./backups` on the host. That works, but it is a host
folder rather than a volume Docker manages, and the stream crosses the Docker API.

## Decision

* A named volume `pgbackups` is mounted at `/backups` in the `db` container.
* `scripts/backup.sh` runs from the host but does the work inside the container:
  `pg_dump --format=custom --compress=6` to a `.partial` file, `pg_restore --list` to
  prove it is readable, rename, `sha256sum`, then retention (newest `BACKUP_KEEP`).
* The file name is generated by the **container clock in UTC**
  (`analytics_20261021T140641Z.dump`). Two hosts with different time zones or a
  drifting clock (seen: WSL2 vs Windows, ~1.5 min) would otherwise produce names that
  sort out of order, and retention would delete the newest backup.
* `backup.sh --export DIR` copies a backup out with `docker compose cp` for off-host
  storage; `restore.sh` accepts either a name in the volume or a host file.

## Options considered

| Option | For | Against |
| --- | --- | --- |
| Named volume, work done in the container | Matches the brief; Docker-managed; no stream through the API; one clock names every file | Need `--export` / `docker compose cp` to see files on the host |
| Bind mount `./backups` (ADR-0004) | Files visible on the host directly | Not a Docker volume; host-side permissions differ per OS |
| Separate backup service with cron | Fully self-contained | Another long-running container for a nightly job; cron on the host is simpler |

## Consequences

* `docker compose down -v` removes `pgbackups` together with `pgdata`. Export first.
* Restoring from another machine: copy the `.dump` (and `.sha256`) over, then
  `scripts/restore.sh <file> --yes`.
